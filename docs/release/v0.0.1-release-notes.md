## What this is

Fornax v0.0.1 is the first tagged release of an evidence-first integrity
system for coding agents. It answers one question in real time: **what
should I believe about what this agent is telling me, given the evidence
currently available?**

It watches a Claude Code or Codex CLI session, captures immutable evidence
(tool calls, exit codes, transcripts) as the session runs, and checks the
agent's own claims against that evidence — surfacing one of five verdicts,
never a made-up trust score:

`VERIFIED` · `UNVERIFIED` · `CONTRADICTED` · `REVIEW` · `UNAVAILABLE`

## What's included

- A local daemon (`fornax-daemon`) with an on-disk SQLite store, a Unix
  domain socket, and a localhost HTTP API + dashboard. **No cloud
  dependency on this path.**
- Adapters for **Claude Code** and **Codex CLI**. These are not equivalent —
  see `docs/research/adapter-capability-matrix.md` for the exact,
  empirically verified differences (Codex's primary integration is
  rollout-file tailing, not hooks; several Claude Code hook capabilities
  have no Codex equivalent yet).
- A CLI (`fornax status` / `fornax detail`) and dashboard showing the same
  claim/evidence/verdict/rationale.
- Optional export to a local, cloud-shaped stack
  (`fornax-uploader` → ingest → Pub/Sub emulator → backend → Postgres →
  SaaS UI) for anyone who wants to run the full pipeline locally. Cloud
  sync is **off by default** and opt-in
  (`FORNAX_CLOUD_SYNC_ENABLED`).

Reproduce the core "aha moment" from a clean checkout with the Quick Start
in `README.md` — no cloud account, no external service, one terminal.

## What this is not

- Not a hosted Beta or production SaaS product. Nothing is deployed for
  you; the cloud-shaped stack above is something you run locally if you
  choose to.
- Not an enterprise governance product.
- Does not perform causal verification or deception/lie detection. Fornax
  checks stated claims against captured tool-call evidence — it does not
  infer intent.
- Not a finished, stable on-disk format. `$FORNAX_HOME`'s schema may change
  in a later version without a migration path yet.

## Known limitations

- Codex CLI support has real capability gaps versus Claude Code (see the
  adapter capability matrix linked above) — hooks on the Codex side are
  opt-in, unstable, and can be admin-disabled; the durable integration
  point is the rollout-file tailer.
- `npm audit` on the docs site (Docusaurus dev-server dependency chain)
  currently reports findings that affect the local dev server only, not
  the published static site — see
  `docs/release/v0.0.1-qa-security-signoff.md` for the full disclosure.
- No live fuzzing, no live Playwright script-injection pass, and no full
  live-stack redaction-pipeline run were performed for this release — this
  is disclosed explicitly, not rounded up to a pass, in the sign-off
  record.
